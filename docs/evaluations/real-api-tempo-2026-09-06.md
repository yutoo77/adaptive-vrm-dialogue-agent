# 実API対話の再確認 — 2026-09-06

## 結論と範囲

所有者の明示承認後、OpenAI Responses APIへ固定の架空入力3件を送信し、**3/3件で文章・制限付き演技データの生成に成功**した。最初の文字までの時間は752〜4,451 ms、本文完了は1,536〜5,350 ms。途中表示の文章と確定文章は全件一致した。

今回はBackendのHTTP Streaming確認であり、ブラウザ・VRMの描画・音声再生は含まない。実API用サーバーは起動できたが、その後のローカル音声エンジン起動コマンドが実行環境に拒否された。別経路から音声エンジンを起動する迂回はせず、Textと演技データだけを独立に確認した。拒否の原因自体は特定できていない。

したがって、以前の「実API評価を実行できない」という状態からは前進したが、**現行UIで実API → 実VOICEVOX → VRM発話を通した最新の評価は未完了**。以前のGPU + Mock音声の数値と足し合わせて、実会話の発話開始時間を推定しない。

## 条件

- 既存モデル`gpt-5.6-luna`、`reasoning.effort=none`、出力上限240 tokens、返答スタイル`balanced`。モデル・Prompt・演技補正は変更していない。
- `scripts.tempo_server:create_app`の専用Backend、localhost:18001。APIキーは既存のBackend環境変数から読み、ファイル・ログ・Frontendへ出力しない。
- 固定入力だけを許可、最大3試行、SDKの自動再試行0回。実際のattemptsも3で、追加リクエストは実行していない。
- ケースごとに新しいSession。直近履歴・関連長期記憶・要約は空、SQLiteは開かずRAMのみ。
- `store=False`。これはOpenAI側のZero Data Retention保証ではない。
- 送信するデータは既存の自作Character ProfileとSchema、以下の架空入力。録音・研究情報・実際の個人会話は使用しない。

## 測定結果

Python HTTPXの単一Client（localhostへの通信は`trust_env=False`）から`POST /api/dialogue/stream`を順番に実行。送信直前から最初の`text_delta`とストリーム終了までをwall timeで測定した。

| ケース | 最初の文字 | 本文完了 | Text Delta数 | 入力 / Cached / 出力 tokens |
| --- | ---: | ---: | ---: | ---: |
| 自己紹介 | 4,451 ms | 5,350 ms | 74 | 1,531 / 0 / 117 |
| 疲れた場面 | 1,295 ms | 2,049 ms | 51 | 1,542 / 1,504 / 94 |
| APIの説明 | 752 ms | 1,536 ms | 69 | 1,530 / 1,504 / 112 |

全件で`complete`を受信、errorイベント0件。Text Delta連結と確定本文が一致。演技は`gentle`、強度0.4、`small_nod`、途中Cueなし。声のスタイルだけは`warm / gentle / warm`だった。

初回には接続やキャッシュの準備が含まれる可能性があり、後続2件ではcached inputが記録された。ただしケースごとに文章が異なるため、「キャッシュだけで何秒短縮した」とは断定できない。各ケース1回であり、連続会話の記憶・感情持越し・未知入力への一般化も評価していない。

### 固定入力と実際の返答

1. 入力: 「こんにちは。あなたの名前と、どんなふうに話してくれるか教えて。」
   返答: 「こんにちは。わたしは月白しずくです。穏やかで自然な日本語で、要点を簡潔にお伝えしながら、あなたの考えや選択を尊重して話します。わたしはAIなので、分からないことは分からないと正直に伝えますね。」
2. 入力: 「架空の話だけど、今日は失敗して少し疲れた。解決策より、少し話を聞いてほしい。」
   返答: 「そっか、今日は失敗があって、少し疲れたんだね。今は解決策を急がずに聞くよ。よければ、いちばん心に残っていることから話して。」
3. 入力: 「APIって何？初めて聞く人にも分かるように教えて。」
   返答: 「APIは、アプリやサービス同士が情報をやり取りするための「窓口」です。たとえば天気アプリが天気情報を表示できるのは、天気サービスのAPIに「東京の天気を教えて」と頼み、結果を受け取っているからです。」

実装担当による読解上の評価: 名前とAIであることは明示でき、疲れた場面で解決策を押しつけず、説明には具体例がある。一方、自己紹介は方針説明が多く、自然なキャラクター会話としてはやや硬い。全3件の表情・しぐさが同じなので、この結果だけでは表情差分の見せ方を評価できない。これは利用者による聴取・体験評価ではない。
