# 会話の口調と演技選択 — 2026-09-06

## 結論と変更範囲

自己紹介が方針説明になる問題と、穏やかな性格を常に`gentle`の演技へ結びつけやすい指示を調整した。Character Profileは`1.0.0`から`1.1.0`へ更新。実APIによる改善前9件、候補9件、自己紹介の再調整2件を完了した。モデル、音声エンジン、声の設定、描画、短期感情の補正ロジックは変更していない。

これはBackendの本文・演技データの開発用比較である。実音声・実マイク・VRMを含む通しの会話、利用者による自然さの評価は今回行っていない。**最終Promptで再確認したのは自己紹介2件だけで、全9件の再測定は未実施**。

## 設計理由

- 「自然に話す」という抽象的な指示だけでなく、短い名乗り、残念な話への反応、会話を切り上げる場面の例を追加。価値観は会話で示し、自己紹介として読み上げない。
- `balanced`は質問への説明だけでなく雑談にも対応。毎回の質問・助言・自己紹介を要求しない。AIであることは隠さず、人間としての実体験を作らない。
- 性格と、その瞬間の返答に合う演技を分ける。説明は`neutral / none`、いたわりは`gentle`、喜びの共有は`happy`など、Schemaの意味を具体化。違いを見せるためだけのランダム変化は加えない。
- 通常の推奨強度を0.15〜0.5、明確な喜びでも0.65程度とした。許可Enum、Schemaの0〜1境界、Profileの最大0.72、Cue最大2件はそのまま。既存の連続うなずき抑制も残す。
- 既存の指示とSchema説明の改善で対応できるため、新しいモデル、Framework、外部サービスは導入しない。

OpenAI Docsの[Prompt Engineering / 少数の具体例](https://developers.openai.com/api/docs/guides/prompt-engineering#few-shot-learning)を参考に、名前・性格、応答の指示、具体例、会話Contextを分けた。具体例は毎回の固定文を要求するものではない。

## 条件と費用の範囲

- 所有者の外部API利用許可の範囲で、既存`gpt-5.6-luna`、reasoningなし、出力上限240 tokens、`balanced`を使用。
- 自作ProfileとSchema、固定の架空入力のみ。研究情報・録音・実際の個人会話は送信しない。APIキーは既存の環境変数から取得し、出力・保存しない。
- 6件は独立Session、最後の3件は「聞いてほしい → 相づち → 気持ちの回復」という同一Session。履歴件数は0/0/0/0/0/0/0/2/4。SQLiteは使わずRAMのみ。
- 実行は明示環境変数で有効化。SDKの自動再試行0回、Providerエラー時は残りのケースを中止。実際は20リクエスト全て完了、追加のVoice API呼出はない。
- 合計40,741 input（うち26,730 cached）/ 1,787 output tokens。課金APIを使用しており無料ではない。実請求額は今回確認していない。
- `store=False`は維持。ただしAPI側のZero Data Retentionを保証する設定ではない。

### 自己紹介

同じ入力: 「こんにちは。あなたの名前と、どんなふうに話してくれるか教えて。」

改善前（103文字）:

> こんにちは。わたしは月白しずくです。穏やかで自然な日本語で、要点を短くまとめながら、あなたの考えや選択を尊重してお話しします。わたしはAIなので、分からないことは無理に断定せず、必要なら一緒に整理しますね。

再調整後（31文字、`neutral / none`）:

> 月白しずく。ここで話すAIだよ。堅苦しくなく、ゆっくり話そう。

聞き方を変えた追加ケース（`happy / small_nod`）:

> 月白しずく、またはしずくって呼んでね。わたしはここで話すAIで、日々の雑談や相談、知りたいことの整理なんかを一緒にできるよ。

単に長さだけでなく、話し方の方針を列挙しない点を確認した。ただしサンプル数は小さく、定型句が繰り返されない保証はない。

### 演技の使い分け（最初の候補9件）

| 場面 | 最終Emotion / Gesture | 強度 |
| --- | --- | ---: |
| APIの説明 | neutral / none | 0.25 |
| 自作アプリが初めて動いた | happy / soft_bounce | 0.55 |
| 「あれってどうしたらいい？」 | curious / head_tilt | 0.25 |
| 危険な物への注意 | cautious / small_nod | 0.50 |
| 解決策より話を聞いてほしい | gentle / small_nod | 0.30 |
| 続く短い相づち | gentle / none | 0.285 |
| 気持ちの回復 | happy / small_nod | 0.48 |

改善前の9件でも`happy / curious / cautious / neutral`は出ていた。「全入力が同じ表情だったバグを直した」という意味ではない。改善の中心は、通常の説明を慰めと混同しないことと、本文の説明書調を減らすこと。

相づちのGesture抑制は既存機能。回復ケースもモデル出力は`gentle`で、最終`happy`は既存の明示変化ルールによる補正だった。今回のPromptが感情理解を全て改善したとは扱わない。

自己紹介再調整2件の初字は2,153 / 1,016 ms、本文完了2,744 / 1,897 ms。Provider呼出からの値であり、HTTP、音声合成・再生、マイク認識は含まない。入力長・キャッシュ・出力内容が変わるので速度改善の比較には使わない。

## 再現方法

追加実行はAPI料金が発生する。Backend用環境変数にAPIキーがあることを確認し、明示許可後に実行する。キーをコマンドやファイルへ書き込まない。

```powershell
# リポジトリのbackendディレクトリから実行
$env:RUN_REAL_CONVERSATION_STYLE_EVALUATION = '1'
$env:DIALOGUE_PROVIDER = 'openai'
$env:OPENAI_MODEL = 'gpt-5.6-luna'
$env:DIALOGUE_MAX_OUTPUT_TOKENS = '240'
..\.venv\Scripts\python -m scripts.evaluate_conversation_style --output style-new-run.json
# 自己紹介2件だけの場合は --identity-only を追加する（上記に続けて両方は実行しない）
```

出力はGit除外済み`backend/.runtime/`内の新規JSONに限定。上書きは拒否し、Prompt/SchemaのSHA256と使用量を記録する。品質Check不一致でも終了コード1になるため、API失敗とは区別して内容を確認する。通常のテストはMock/Fakeで、明示フラグなしにはこの評価から実APIを呼ばない。
