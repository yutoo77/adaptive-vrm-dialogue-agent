# ローカル音声認識の時間分解と軽量設定比較

2026-09-13 / Windows / cached faster-whisper small、CPU/int8、VOICEVOX 0.25.2。アプリのbeam size（認識候補の探索幅）は5のまま維持した。

## 方法と再現

自作5文を既存VOICEVOXで合成し、同じWAVをRAM内で各2回認識する。Model取得は禁止し、取得済みcacheだけを読む。音声・Model・環境変数をGitに追加しない。マイク、研究資料、既存録音、LLM API、通常会話/記憶は使わない。

```powershell
cd backend
..\.venv\Scripts\python -m scripts.evaluate_transcription_latency --run-local
# 上記10認識に加え、同じ5音声をbeam 5/1で各2回比較（追加20認識）
..\.venv\Scripts\python -m scripts.evaluate_transcription_latency --run-local --compare-beams
```

Flagなしでは実処理しない。VOICEVOX合成を全て終えてから認識を測り、Model構築と、遅延生成されるSegmentを最後まで読む時間を分ける。比較ではRound 1が5→1、Round 2が1→5。実行回数は固定。Benchmarkはアプリ設定を変更しない。

## 結果

音声長は2.240〜3.744秒。Aは標準10認識、Bは標準10認識に20件の対比較を追加した別ProcessのRun。

| 測定区間 | Run A | Run B |
| --- | ---: | ---: |
| Model構築 | 2,255ms | 2,446ms |
| 最初の認識 | 3,213ms | 3,665ms |
| 残る9認識の中央値 | 2,803ms | 3,507ms |
| 残る9認識の最小〜最大 | 2,639〜2,991ms | 3,251〜3,657ms |

Bの対比較（事前の10認識で初回処理を済ませたModelを共用）:

| 対象 | 中央値 |
| --- | ---: |
| beam 5 | 2,925ms |
| beam 1 | 2,707ms |
| 各対の短縮量（5−1） | 187ms |

10対全てで、句読点/空白/文字幅を正規化した認識文は同じだった。ただし一つの対ではbeam 1の方が200ms遅く、Run間にも変動がある。単発の差を安定した速度保証として扱わない。

## 認識文を点検した結果

標準・軽量とも、各10認識の文字一致は4件。これは「認識精度40%」という意味ではない。

- 「今日は少し忙しかったから、ゆっくり話したいな」「丸い月を真ん中に置いてみよう」は句読点以外が一致。
- 「右の栞を、一度外してみて」の栞が「塩利」になった。
- 「ヒントはまだ言わないで。一緒に考えたい」のヒントが「キント」になった。
- 「声の速さを少しゆっくりにしてほしい」の速さが「はやさ」になった。これは表記差であり、意味を失った誤認識とは分ける。

合成音声自体の発音と認識器のどちらに起因するかは聴取比較していない。少数の単語を正解へ機械置換する対処はせず、利用者が認識Draftを直せる経路を維持する。

## 判断と限界

探索幅を減らした短縮はこの測定で約0.19秒にとどまり、数秒の待ちを解消しない。5文で出力が同じでも、雑音、否定、固有名詞、数字、実話者の品質を保証できないため既定5は変更しない。事前Model読込を別の明示起動Optionとして用意するが、VAD初期化や最初の推論まで消すものではない。

本測定はModel内時間。話し終わりの無音待ち、録音終了、HTTP、Draft確認、LLM応答、発話開始を含まない。全工程の自然さや実マイク精度、長時間安定性を示す評価ではない。VRM画面や他Processを完全に止めた専用Benchmark環境でもない。

ScriptのFake testsは、認識10件/比較20件の上限、同一Clipと順序反転、local_files_only、遅延Segment時間の計測、Flagなし/VOICEVOXなしでの非実行を確認する。実行した外部AI Requestは0件。音声はRAMのみで保存しない。
