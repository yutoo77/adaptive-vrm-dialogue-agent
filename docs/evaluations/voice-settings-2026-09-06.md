# 声のカスタマイズと利用者フィードバック — 2026-09-06

## できるようになったこと

設定の音声ページで声・スタイル、速さ（0.6〜1.6）、高さ（-0.15〜0.15）、抑揚（0〜1.5）を調整する。短い固定文の試聴・停止、標準値への復帰、ブラウザ再読込後の復元まで実装した。今回の実機ではVOICEVOX 0.25.2から会話用127スタイルを取得できた。人数ではなくスタイルの数であり、別PCではインストール状況に依存する。

「声を試す」はLocal VOICEVOXだけを使い、LLM呼出や会話履歴追加はしない。追加Dependencyなし、追加の課金サービスなし。試聴文には読みの確認用に「忙しかった分」を含めた。

声の設定は発話開始時にコピーし、文単位に合成しても一つの返答の途中で切り替わらない。変更は次の発話から適用する。速度調整はWAVの合成パラメータで行い、母音Timingは出来上がったWAVの長さへ合わせる。既存の演技による小さな再生速度の補正は引き続き適用される。

## 原因の切り分け

### 声を変更できなかった理由

VOICEVOXには話速・音高・抑揚の調整機能があるが、アプリがCharacter Profileの固定値をAudioQueryへ設定していた。今回、利用者の選択を任意の`voice`として音声APIへ渡すようにした。設定なしの既存リクエストは従来の既定値で動く。

Backendは数値範囲と実際に利用できる会話用Style IDを検証する。別Sessionの声に影響しないよう、共有Providerの値やVOICEVOX本体の設定を書き換えない。Frontendは検証済みの数値4項目だけを`localStorage`へ保存する。通常の会話・録音・APIキーは含めない。

### 「忙しかった分」を「わけ」と読む

同じEngine・speaker 14の`audio_query`で再現できた。

| 渡した文 | Engineの読みの該当箇所 |
| --- | --- |
| 忙しかった分 | ブン |
| 忙しかった分、少し休もう。 | ワケ |
| 今日は忙しかった分、ゆっくり過ごしてね。 | ワケ |
| 忙しかったぶん、少し休もう。（補正後） | ブン |

今回はLLM本文や音声認識ではなく、VOICEVOXの文章から読みを選ぶ段階で発生していた。音声合成の入力だけ「忙しかった分 → 忙しかったぶん」と補正した。画面や会話履歴の漢字は保持し、「五分」「自分」「分かる」などへ一律置換しない。これだけで一般の誤読を解決したわけではなく、ほかの例は個別に確認する必要がある。VOICEVOXの共有ユーザー辞書は変更していない。

### 音声入力の待ち時間

稼働中の設定はfaster-whisper `small / cpu / int8`、beam size 5。録音終了後に全体を送信・認識し、認識完了後に入力欄へ戻す。初回だけモデルを読み込む。

再起動後、Local VOICEVOXで生成した2.763秒の固定音声を同じBackendへ2回送信した。実マイク・利用者録音は使わず、WAVはメモリ内だけで扱った。

| 条件 | HTTP往復 | Backend処理 |
| --- | ---: | ---: |
| 再起動後の初回・モデル未読込 | 5,149 ms | 5,146 ms |
| 同じ音声の2回目 | 2,386 ms | 2,376 ms |

初回準備の影響があると考えられるが、準備後にも約2.4秒かかる。各1回の合成音声による診断であり、実マイク精度や代表的な性能を示す評価ではない。今回は認識モデルや設定を変更していない。次は実マイクで録音終了から表示までを測り、CPU/GPUや軽量モデルの速度・精度を比較する。初回準備だけで解決したとは扱わない。

## 実音声の確認

固定文「こんにちは、しずくだよ。忙しかった分、少し休もう。」を4条件で合成した。全条件で有効なWAVと20区間の母音Timingを確認し、TimingがWAVの範囲内であることを検証した。各WAVのハッシュも異なった。WAVは公開・保存していない。

| 条件 | speaker | 話速 / 音高 / 抑揚 | WAV長 |
| --- | ---: | --- | ---: |
| 標準 | 14 | 0.96 / -0.01 / 0.94 | 4,811 ms |
| ゆっくり・低く | 14 | 0.75 / -0.05 / 0.94 | 6,048 ms |
| 速く・高く | 14 | 1.30 / +0.05 / 0.94 | 3,531 ms |
| 別の声 | 3 | 0.96 / -0.01 / 0.94 | 5,525 ms |

WAV長の差は話速指定が反映された証拠になる。高さ・声質の主観的な好みや自然さを、自動検証だけで合格にはしない。今回の開発側の検証ではOpenAI APIを呼んでいない。
